# 毛毯 A+ 内容设计 v4.1

## 本次设计方法更新

v4.1（2026-10-31）：继承visual-v4，增加信息精简、文字层级与七图视觉节奏审核。 旧版名称继续对应稳定调用标识，不新增重复技能。
生成前和视觉返工时读取[设计适配与检查](references/design-review.md)，按其中链接使用共用的Impeccable位图适配方法：明确目标与锁定区域，选择必要调整，检查最终成图。只改文字/布局时优先本地处理，方法检查并入已有审核，不增加默认交付物或审图接口。

旧版调用名称继续有效，均使用当前新版。用户于2026-10-29确认三图视觉试验优于旧版，后续默认`visual-v4`：完整摄影场景、无固定侧栏、无衬线字体、精确本地排版、印花选区放大和居中款式名称。使用[新版视觉规则](references/visual-v4.md)和实际排版器，不恢复旧模板作为新任务默认。

所有A+图片不显示品牌名、商标或水印；brand仅作内部店铺归属记录，不写入可见文案或生图提示词。参考图如带品牌标识须换用干净素材。逐图检查包含场景中物品、服装、洗衣机是否出现标识。

先按用户确认区分`finished`成品与`custom`定制照片毛毯。定制时读取[定制七图分支](references/custom-seven.md)：照片是示例，款式对应照片数量/布局；第02页改为照片与布局选择说明，不沿用成品选印花文案。实际上传界面、文字定制和预览功能未经核实不展示。

稳定标识 `$blanket-aplus-design`；旧名称v1.0/v2.0仍指本技能。作图 → A+内容设计。遵循[工具库规范](../../skill-library/PRINCIPLES.md)，生图只用现有共享image-runtime。

## 默认交付

用户目录只交付**7张970×600 PNG**，包含英文，不默认生成报告、独立文案、网页、总览或ZIP。内部工程放工作区output/aplus，保留必要提示词、来源、调用状态与简短审核，以便断点恢复；不复制进交付目录。需要额外文件时按用户要求启用。

七张依次回答：产品是什么、正面/材质细节、有哪些款式、在哪里使用、四尺寸、如何洗护、礼赠。四尺寸固定30×40、40×50、50×60、60×80英寸；父体实际全部款式必须完整覆盖。品牌、款数、图案和场景不写死，当前支持1至10款。

## 高效执行

1. 读取当前父体资料；有已核实清单时增量检查，不重新扫描无关历史项目。读取[项目合同](references/seven-image-contract.md)及[模块提示词](references/seven-module-prompts.md)中与本次有关的部分，不重复外部检索或制作长分析报告。
2. 建立schema_version=2、profile=parent-seven、layout=visual-v4简报。先按当前父体确定配色、构图和文字区域，再写场景提示词。优先现成合格素材，改变文案/排版不调用生图。跨修订复用通过scene.reuse_from指定旧工程，程序核对品牌、父体、款式、尺寸、提示词、参考图和原始结果哈希；改变场景要求就生成新素材，不冒充复用。prepare默认新版，拒绝普通新任务指定旧版式。
3. prepare在付费前校验文字区域、长文案、裁切和款式布局，再generate dry-run。全新风格先审一个代表场景，改版沿用已确认风格可直接生成需要返工的场景。默认最多2个并发请求，由单个运行进程维护状态；不降低model、quality或分辨率换速度。不为每张图重复调用多个审图服务；统一检查焦点、层级、真实比例及手机可读性。
4. render默认只合成7图及内部检查记录。生成完成的素材自动跳过；不要为了看到更多候选多次请求。失败或结果不明先检查状态，局部失败仅修该模块，不整批重跑。
5. 目视检查每张成图，并在内存/临时预览中缩到375px检查关键文字。准确尺寸与款式集合自动校验；视觉不能用“文件存在”代替。只记录简短问题与结论，未解决的材质、尺寸、图案或文字问题不得标通过。
6. export输出到新目录，严格只含7张PNG。保留旧成图，不自动覆盖。无须生成ZIP/HTML才能交付。

## 视觉与事实底线

- 01明确产品类别，例如Printed flannel / blankets.；完整场景里预留自然墙面放字，图像与文字区域按同一坐标约定。文字不能遮住产品、脸部或靠垫；禁止用旧固定白侧栏兜底。必要时改文字区域或场景，不靠缩小字体硬塞。
- 02优先有来源的实拍绒面/包边，可通过detail_photo登记；没有实拍时使用完整正面＋选区标注＋对应大幅原图局部，说明Enlarged print detail。不把画中人物衣服、草丝、皮毛等变成毛毯工艺证明；明确记录素材性质。定制分支仍为布局/照片/尺寸选择说明。
- 03用实际毛毯正面，必要时裁掉白底外边距但保留包边。1至4款一行，5至10款两行，末行居中；名称居中，完整覆盖。定制显示实际照片数，同照片数不同布局再区分Layout A/B。不遗漏、拼成同一条毯子或暗示购买整套。
- 04尺寸用可见家具、毯边终点、未覆盖身体部位辅助判断；小毯不能仅在提示词写小尺寸却画成整身落地。摄影场景不等于精确测量，比例存疑记录原因并返工或改选素材。
- 05同一比例画四尺寸，每个标签直接包含in单位；不以年龄或床型适用保证代替尺寸。可用统一参照但不能挤掉关键数字。
- 06Machine Washable作为主信息；水温、烘干、漂白、永不褪色均需独立证据。07展示明确递出/接住动作、自然目光及可识别印花，包装未知不加礼盒/丝带。
- 主标题约40–44px，四款名称36px，多款标签30px起步，辅助字28px起步；全部按375px实看。优先删重复副标题，不为了塞字无限缩小。固定PNG不能在手机自动重排。
- 成品不写Custom/Personalized/Upload Your Photo；共同卖点必须对父体相关款式都成立。素材来源为生成图时不假称实拍。

## 命令

使用`<PYTHON> -X utf8`执行`scripts/campaign.py`：

```text
prepare --brief brief.json --out 内部新工程
generate --project 内部新工程
generate --project 内部新工程 --execute --concurrency 2
render --project 内部新工程
check --project 内部新工程
export --project 内部新工程 --out 用户目录/新版本七图
```

仅用户需要时用render --full生成文案/网页，package生成完整设计稿ZIP。旧schema1由workflow.py维护；旧版式仍可恢复。并发失败保留已成功任务，确认失败原因后以--module和--retry-note重试。

默认精简模式不等于减少视觉检查。当前流程不发布商品；7张成图不保证目标店铺可用7个Basic A+独立槽位。定制分支支持已确认的照片定制与选款说明，不代表已验证店铺的Amazon Custom设置。

历史工程和旧成图不删除。`--restore-legacy-layout`仅用于用户明确要求复现历史工程，不用于日常新任务。常规交付仍为七图；三图试验、对照网页、报告只在用户明确要求时生成。
